# Batching experiment: REJECTED
Shared size-class slab buffers + glMultiDrawArrays reduced MV1 CPU submission
from ~9 ms to ~0.1 ms and moved the 240 m/s cardinal worst from ~18.5 ms to
~16.85 ms. BUT glBufferSubData into slabs still in flight caused reproducible
50-98 ms gameplay-frame engine stalls (4/5 Test B runs failed the hard gate;
mv1_runtime_slab_allocs_after_warmup=0 ruled out creation; --mv1-off clean).
It was therefore REVERTED. Per-tile persistent/recycled VBO ownership remains
the certified gameplay-safe path (0 stalls, 6/6 Test B green).

# Kept from this investigation (all image-identical, gameplay-safe)

- Canonical draw order (band -> abs tile Y -> abs tile X -> tile key): deterministic
  z-tie resolution. One equal-depth pixel at station "ridge_shoulder" changed its
  deterministic winner; MV1.C + MV1.D station2 images re-baselined once and frozen
  (byte-stable across repeated runs).
- Per-tile VBO ownership, bounded build budget, MV1.C two-pass 32 km raster,
  MV1.D aerial perspective — unchanged.
